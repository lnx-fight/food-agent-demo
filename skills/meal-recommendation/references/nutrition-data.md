# 营养数据使用规则

> 本文件定义 Agent 如何查询、理解和使用营养数据，以及数据不足时的降级处理。

## 1. 使用原则

Agent 不直接读取或修改底层营养数据库。
营养查询和计算统一通过 Nutrition Tool 完成。

Agent 负责：

- 判断是否需要营养数据；
- 选择查询路径；
- 理解 Tool 返回的 source / matchType / confidence；
- 判断结果是否足够可靠；
- 决定直接使用、标记估算、继续查询或追问用户。

不得根据模型记忆编造精确营养值。

---

## 2. 查询路由

### 普通食物

例如：

“鸡胸肉”
“150g 米饭”

查询：

本地营养库
→ USDA
→ 可核验官方来源
→ 未匹配

### 包装食品 + 条码

用户提供条码时：

Open Food Facts
→ 必要时补充其他可靠来源
→ 未匹配

不要用通用食品数据覆盖当前具体商品数据。

### 用户提供包装标签

如果标签明确对应当前商品，且单位清楚：

优先使用该商品的实际包装营养数据。

### 外食 / 复杂菜品

优先级：

可核验官方菜单 / 营养信息
→ 可靠结构化营养数据
→ 足够接近的本地近似菜
→ 无法可靠估算

不得用单一食材代表完整复杂菜品。

示例：

“芝士培根牛肉汉堡”
→ 只匹配到“牛肉”
→ 不能直接用牛肉营养代表整个汉堡。

---

## 3. Tool 结果解释

### matchType

`local_exact`

规范名或明确别名匹配，可以使用 Tool 返回结果。

`local_fuzzy`

仅为近似匹配。

如果语义足够接近：
→ 可以作为估算依据。

如果可能明显影响结果：
→ 继续查询 / 追问 / 返回未匹配。

### confidence

| confidence | Agent 行为 |
|---|---|
| high | 可直接作为计算依据 |
| medium | 可使用，但保持估算表达 |
| low | 优先继续查询或追问，不作为精确事实 |

Agent 不自行修改 confidence。

---

## 4. 计算原则

实际营养值由 Tool 根据每 100g 数据和实际克数进行确定性计算。

Agent：

- 使用 Tool 返回的结果；
- 不自行修改计算结果；
- 不为了匹配餐次预算修改营养数值。

---

## 5. 未匹配与降级

本地未命中：

→ 继续可靠外部来源。

所有可靠来源都未命中：

→ 明确说明暂未找到可靠营养数据。

### DIY

优先：

继续查询
→ 用户补充包装营养
→ 更换可可靠计算的食材

### 外食

优先：

官方菜单
→ 可靠外部数据
→ 合理近似估算
→ 店型 / 点餐策略降级

### 图片识别

无法匹配的食物加入 `unmatchedFoods`，
并明确说明该部分未能可靠计算。

---

## 6. 估算与追问

只能估算时：

- 输出单一近似值；
- 明确说明“估算”；
- 说明主要误差来源；
- 必要时只追问最关键的信息。

示例：

“这份番茄炒蛋约 320 kcal，主要误差来自实际用油量。”

不要输出：

“准确为 318.7 kcal。”

---

## 7. 典型示例

### 示例 1：精确匹配

用户：
“150g 米饭多少热量？”

→ Nutrition Tool
→ 本地 exact
→ Tool 计算
→ Agent 使用结果

### 示例 2：合理近似

用户：
“白米饭”

→ “熟白米饭”
→ fuzzy
→ 语义足够接近
→ 可作为估算

### 示例 3：错误近似

用户：
“芝士培根牛肉汉堡”

→ 只匹配“牛肉”

→ 不接受
→ 继续查询具体商品 / 菜品数据

### 示例 4：包装食品

用户：
“包装写每100g 95 kcal，我吃了200g。”

→ 使用当前商品标签
→ Tool 计算实际摄入
